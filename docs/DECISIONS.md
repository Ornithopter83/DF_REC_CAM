# 결정 기록

이 문서는 프로젝트에서 결정된 사항만 짧게 기록한다. 대화 요약을 장문으로 남기지 않는다.

## 형식

```text
YYYY-MM-DD
- 결정 내용
- 이유 또는 영향
```

## 2026-06-26

- 긴 대화 이주용 요약을 반복 작성하지 않는다.
- 프로젝트 맥락은 대화가 아니라 저장소 문서에 둔다.
- 작업은 `tasks/*.md` 단위로 나누어 수행한다.
- 작업 완료 후 새로 생긴 결정사항만 `docs/DECISIONS.md`에 짧게 추가한다.
- 녹화/재생 전용 배포 모드는 실행 인수 `--reconly`로 켠다.
- 기본형에 가까운 지역 변수는 우항 타입이 명확하면 `var`보다 명시 타입을 우선 사용한다.

## 2026-07-15

- UI 외관 개선에는 Krypton Toolkit을 도입한다.
- 기능/성능 개선이 아니라 기본 Windows Forms 앱 느낌을 줄이는 차분한 밝은 테마 적용을 목표로 한다.
- 영상 표시, 녹화, 감지, 재생 흐름은 UI 테마 변경과 분리해 유지한다.
- 상태 중심 UI는 승인된 디자인 시안의 정보 계층과 색상을 최대한 따르되 실제 제공되는 상태 데이터만 표시한다.
- 녹화 일시 정지, 실시간 수신 비트레이트, 네트워크 상태, 이벤트 배지, 저장 경로 변경처럼 현재 동작이 없는 항목은 UI 시안만을 근거로 새 기능화하지 않는다.
- 저장소 동작은 기존 `AppPaths.RecVideos` 정책을 유지하고 화면에는 실제 경로를 읽기 전용으로 표시한다.
- 메인 오른쪽 작업 영역은 녹화와 파일 재생을 별도 탭으로 분리하며, 영상 불러오기는 재생 탭에서만 제공한다.
- 전체화면에서는 영상 외의 상단 헤더, 오른쪽 작업 영역, 하단 상태바와 레이아웃 여백을 모두 숨긴다.
- 전체화면에서는 카메라 종류와 FPS를 포함한 영상 오버레이도 표시하지 않는다.
- 빠른 작업 그룹은 유지하지 않고, 설정 진입은 녹화/재생 탭에 영향을 받지 않는 상시 톱니바퀴 버튼으로 제공한다.
- 이벤트 로그 진입점은 메인 화면에서 제거하고 설정창의 전용 페이지로 통합한다.

## 2026-08-03

- 트레이 숨김과 복원은 재진입 방지 상태를 사용하는 멱등 동작으로 유지하며, 최소화 `Resize`에서는 UI 이벤트 스택 이후 한 번만 숨김을 예약한다.
- USB 카메라 자동 전체 녹화는 첫 프레임 수신 후 10초 워밍업을 거쳐 시작하며, 시작 프레임을 실제 녹화 writer에 즉시 기록한다.
- USB 카메라 속성 지원 여부와 자동·수동 범위는 DirectShow `IAMCameraControl`/`IAMVideoProcAmp` capability 조회 결과를 기준으로 하며, 취소 시 장치의 최초 값을 복원한다.
- 수동 녹화 모드를 선택하면 대기 중인 자동 전체녹화 타이머와 비동기 워밍업을 즉시 취소하고, 녹화 시작 직전에 현재 모드를 다시 확인한다.
- 녹화 중에는 writer 큐를 최우선으로 사용하고 프리뷰를 5 FPS·최대 640x360으로 제한하며, FFmpeg 입력은 프레임별 BMP 대신 `bgr24 rawvideo`를 사용한다.

## 2026-08-07

- 저장소 자동 정리는 각 녹화 유형에 설정된 보관기간을 초과한 MP4만 삭제하며, `MaxStorageGB`와 `MinFreeDiskGB`에 따른 용량 강제 삭제는 사용하지 않는다.
- 디스크 사용률 중단·재개 임계값은 파일 삭제가 아니라 신규 녹화의 중단과 재개에만 사용한다.
- 기존 `settings.json` 호환성을 위해 사용하지 않는 용량 제한 필드는 당분간 유지한다.

## 2026-08-12

- 기기 최초 등록은 `DFBlackbox 등록 요청 → QR 웹 접속 → 로그인 → 관리자 승인 → 앱의 승인 결과 수신` 흐름으로 구현하고 초기 버전에서 SMS OTP는 사용하지 않는다.
- 등록 승인 결과는 구현 단순화를 위해 제한 시간 동안 2~3초 폴링으로 확인한다.
- 클라우드는 장치·카메라 ID와 NAS 상대 경로를 승인하고, 실제 NAS 폴더 생성과 쓰기 검사는 같은 네트워크의 DFBlackbox가 수행한다.
- QR에는 일회용 등록코드만 포함하고, 최초 장치 토큰은 한 번만 발급하여 Windows DPAPI로 암호화 보관한다.
- 일반 카메라의 프레임 단절만으로 실제 전원 꺼짐을 확정하지 않으며, 별도 전원 텔레메트리가 없으면 전원 상태를 `unknown`으로 취급한다.
- 등록 API URL과 NAS SMB 루트는 기존 `settings.json`의 선택 필드로 두되 장치 토큰은 별도 DPAPI 암호화 파일에 저장한다.
- QR 이미지 패키지는 배포 영향 확인 전까지 추가하지 않고, 최초 UI는 등록코드 복사와 승인 페이지 열기를 제공한다.
- NAS 프로비저닝 실패와 서버 결과 보고 실패는 장치 승인 상태와 분리하며, 새 등록 없이 로컬 프로비저닝만 재시도할 수 있게 한다.
- Supabase 프로젝트 URL과 publishable key는 공개 클라이언트 설정이므로 새 `settings.json`의 기기 등록 선택 필드에 기본값으로 저장하고, 요청 시 `apikey` 헤더로만 전달한다. NAS SMB 루트는 배포 환경마다 달라 기본값을 만들지 않는다.
- 공개 테이블은 모두 RLS를 활성화하고, 등록 생성·상태 소비·프로비저닝 보고는 service-role 전용 DB 함수와 Edge Function을 통해서만 수행한다.
- 등록코드와 장치 토큰은 DB에 평문으로 저장하지 않고 SHA-256 해시만 보관하며, 장치 토큰 평문은 승인 결과 조회에서 최초 한 번만 반환한다.
