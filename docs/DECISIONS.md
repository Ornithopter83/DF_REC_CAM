## 2026-06-26

- 긴 대화 이주용 요약을 반복 작성하지 않는다.

## 2026-07-15

- UI 외관 개선에는 Krypton Toolkit을 도입한다.
- 기능/성능 개선이 아니라 기본 Windows Forms 앱 느낌을 줄이는 차분한 밝은 테마 적용을 목표로 한다.
- 영상 표시, 녹화, 감지, 재생 흐름은 UI 테마 변경과 분리해 유지한다.
- 상태 중심 UI는 승인된 디자인 시안의 정보 계층과 색상을 최대한 따르되 실제 제공되는 상태 데이터만 표시한다.
- 녹화 일시 정지, 실시간 수신 비트레이트, 네트워크 상태, 이벤트 배지, 저장 경로 변경처럼 현재 동작이 없는 항목은 UI 시안만을 근거로 새 기능화하지 않는다.
- 저장소 동작은 기존 `AppPaths.RecVideos` 정책을 유지하고 화면에는 실제 경로를 읽기 전용으로 표시한다.
- 메인 오른쪽 작업 영역은 녹화와 파일 재생을 별도 탭으로 분리하며, 영상 불러오기는 재생 탭에서만 제공한다.
- 전체화면에서는 영상 외의 상단 헤더, 오른쪽 작업 영역, 하단 상태바와 레이아웃 여백을 모두 숨긴다.
- 전체화면에서는 카메라 종류와 FPS를 포함한 영상 오버레이도 표시하지 않는다.
- 빠른 작업 그룹은 유지하지 않고, 설정 진입은 녹화/재생 탭에 영향을 받지 않는 상시 톱니바퀴 버튼으로 제공한다.
- 이벤트 로그 진입점은 메인 화면에서 제거하고 설정창의 전용 페이지로 통합한다.

- USB 카메라 자동 전체 녹화는 첫 프레임 수신 후 10초 워밍업을 거쳐 시작하며, 시작 프레임을 실제 녹화 writer에 즉시 기록한다.
- USB 카메라 속성 지원 여부와 자동·수동 범위는 DirectShow `IAMCameraControl`/`IAMVideoProcAmp` capability 조회 결과를 기준으로 하며, 취소 시 장치의 최초 값을 복원한다.
- 수동 녹화 모드를 선택하면 대기 중인 자동 전체녹화 타이머와 비동기 워밍업을 즉시 취소하고, 녹화 시작 직전에 현재 모드를 다시 확인한다.
- 녹화 중에는 writer 큐를 최우선으로 사용하고 프리뷰를 5 FPS·최대 640x360으로 제한하며, FFmpeg 입력은 프레임별 BMP 대신 `bgr24 rawvideo`를 사용한다.

## 2026-08-12

- 기기 최초 등록은 `DFBlackbox 등록 요청 → QR 웹 접속 → 로그인 → 관리자 승인 → 앱의 승인 결과 수신` 흐름으로 구현하고 초기 버전에서 SMS OTP는 사용하지 않는다.
- 등록 승인 결과는 구현 단순화를 위해 제한 시간 동안 2~3초 폴링으로 확인한다.
- 클라우드는 장치·카메라 ID와 NAS 상대 경로를 승인하고, 실제 NAS 폴더 생성과 쓰기 검사는 같은 네트워크의 DFBlackbox가 수행한다.
- QR에는 일회용 등록코드만 포함하고, 최초 장치 토큰은 한 번만 발급하여 Windows DPAPI로 암호화 보관한다.
- 일반 카메라의 프레임 단절만으로 실제 전원 꺼짐을 확정하지 않으며, 별도 전원 텔레메트리가 없으면 전원 상태를 `unknown`으로 취급한다.
- 등록 API URL과 NAS SMB 루트는 기존 `settings.json`의 선택 필드로 두되 장치 토큰은 별도 DPAPI 암호화 파일에 저장한다.
- 사용자 승인에 따라 QRCoder 1.8.0을 추가해 등록 승인 URL을 앱 내부 QR 이미지로 표시한다. QR Bitmap은 교체 및 폼 종료 시 해제하며, 렌더링 실패 시에도 등록코드 복사·승인 페이지 열기·등록 폴링은 유지한다.
- 별도 Dummy 등록 모드는 두지 않는다. 실제 카메라 연결 여부와 무관하게 기기 등록은 항상 운영 Supabase 승인 흐름을 사용하며, 시험 데이터 정리가 필요하면 실제 등록 데이터와 구분해 DB에서 직접 처리한다.
- NAS 프로비저닝 실패와 서버 결과 보고 실패는 장치 승인 상태와 분리하며, 새 등록 없이 로컬 프로비저닝만 재시도할 수 있게 한다.
- Supabase 프로젝트 URL과 publishable key는 공개 클라이언트 설정이므로 새 `settings.json`의 기기 등록 선택 필드에 기본값으로 저장하고, 요청 시 `apikey` 헤더로만 전달한다. NAS SMB 루트는 배포 환경마다 달라 기본값을 만들지 않는다.
- 공개 테이블은 모두 RLS를 활성화하고, 등록 생성·상태 소비·프로비저닝 보고는 service-role 전용 DB 함수와 Edge Function을 통해서만 수행한다.
- 등록코드와 장치 토큰은 DB에 평문으로 저장하지 않고 SHA-256 해시만 보관하며, 장치 토큰 평문은 승인 결과 조회에서 최초 한 번만 반환한다.
- NAS 상대 경로는 UUID 계층 대신 `DFBlackbox/{조직명}/{카메라명}`으로 단순화한다. Windows 금지문자를 `_`로 치환하고 카메라명의 공백을 제거해 `MyCompany/Camera1` 형태로 만들며, 현재 단일 카메라 범위에서는 조직 내 경로 중복을 허용하지 않는 운영 전제를 사용한다.
- 등록 완료 시 웹 승인에서 입력한 등록명과 비민감 식별 정보는 현재 사용자 범위 `HKCU\Software\DFBlackbox\DeviceRegistration`에 기록한다. 장치 토큰은 레지스트리에 넣지 않고 기존 DPAPI 파일에 유지한다.
- 등록 해제는 장치 토큰 인증으로 서버 상태를 `revoked`로 만든 뒤 로컬 레지스트리·설정 식별자·DPAPI 토큰을 정리한다. NAS 폴더와 녹화 데이터는 자동 삭제하지 않으며, 같은 설치 ID를 다시 승인하면 기존 장치·카메라 행을 재활성화한다.
- 승인 웹은 로그인 후 등록코드의 현재 상태를 서버에서 다시 확인하며, `pending` 요청에만 승인·거절 입력을 허용한다. 승인·거절·만료되었거나 존재하지 않는 요청은 읽기 전용 종료 화면으로 표시하고 기존 URL을 다시 열어도 재처리할 수 없게 한다.
- 실시간 송출과 녹화는 별도 인코더를 두지 않고 카메라 프레임을 한 번 H.264로 인코딩한 결과를 공유한다. 녹화 소비자는 MP4로 패키징하고 실시간 소비자는 재인코딩 없이 SFU 인입으로 전달하며, 송출 지연과 장애는 녹화 큐를 막지 않는다.
- 완성된 로컬 녹화는 NAS에 임시 이름으로 순차 복사한 뒤 길이를 검증하고 최종 MP4로 변경한다. NAS 장애 중에는 로컬 원본을 보존하고 주기적으로 재시도하며, NAS 복사가 확인되지 않은 등록 기기의 녹화는 자동 정리에서 제외한다.
- 실시간 미디어 서버는 LiveKit Cloud와 RTMPS Ingress를 사용한다. LiveKit URL·API Key·API Secret은 Supabase Edge Function Secret에만 두며, 웹에는 구독 전용 단기 참가 토큰을, 장치에는 해당 카메라의 RTMPS URL과 stream key만 전달한다.
- 실시간 송출은 웹 시청자가 90초 lease를 주기적으로 갱신하는 요청형 방식으로 시작한다. DFBlackbox는 장치 토큰으로 명령을 폴링하고 lease가 끝나면 송출을 중단하며, Ingress는 카메라별로 한 번 생성해 재사용한다.
- NAS는 원본 보관 경계로 유지하고 웹 미디어 제공용 복사본은 비공개 Supabase Storage에 둔다. DFBlackbox가 NAS `recordings` 폴더를 재검사해 수동 추가 MP4까지 SHA-256 멱등 키와 TUS 이어올리기로 동기화하며, Storage 실제 길이 검증 후에만 웹 목록에 공개한다.
- 웹 녹화 목록은 조직 권한이 확인된 `ready` 항목만 반환하고 재생·다운로드는 5분 signed URL을 사용한다. NAS 절대경로, Storage 객체 경로, 장치 토큰과 서비스 비밀값은 브라우저 응답에 포함하지 않는다.
- Edge Function이 관리자 DB RPC를 호출할 때 opaque `sb_secret_` 키는 `apikey` 헤더에만 전달한다. 사용자 JWT만 `Authorization: Bearer`에 전달하며, DB의 장치 인증 실패는 API에서 401로 변환한다.
- 녹화 `source_fingerprint`는 장치가 계산한 SHA-256 멱등 식별자다. 완료 전 서버는 비공개 Storage 객체의 실제 길이를 검증하지만 현재 Storage 메타데이터로 파일 내용을 다시 해시하지 않으므로, 장치 토큰과 HTTPS/TUS 전송을 신뢰 경계로 둔다.
- 작업서는 `A`, `B`, `C` 형식의 세부 작업 단위로 분리하고 한 번에 1개만 진행한다. 진행 상황은 완료 항목을 소거한 `잔여 작업 n개 (A, B, C, ...)` 형식으로 관리한다.
- 진행 중 새로 발견한 해결 과제는 현재 작업 범위에 임의로 포함하지 않고 별도 지시 대상으로 분리한다.

## 2026-08-13

- RTMPS 송출 실패 재시도는 명령 폴링과 분리해 3초부터 지수 증가시키고 최대 30초로 제한한다. 명령 폴링은 계속해 lease 종료를 놓치지 않으며, `Publishing` 성공·lease 종료·등록 변경 시 재시도 상태를 초기화한다.
- 장치는 `should_stream=true` 응답도 `lease_until`이 로컬 현재 시각보다 이후인 경우에만 실행해 네트워크 지연으로 늦게 도착한 만료 명령의 재송출을 막는다.
- 실시간 보기 중지는 브라우저의 LiveKit Room과 heartbeat를 즉시 종료하되 카메라 단위 서버 lease를 직접 취소하지 않는다. 여러 시청자가 공유하는 합산 lease에서 한 시청자의 중지가 다른 시청자의 송출을 끊지 않게 하고, 마지막 heartbeat 이후 기존 90초 lease 만료로 장치 송출을 종료한다.
- 애플리케이션 파일 로그는 공용 로거에서 미디어 URI와 인증 비밀값을 쓰기 전에 중앙 마스킹한다. 일시적 네트워크·서비스 장애는 비민감 실패 유형만 포함한 WARN으로, 인증 거부는 INFO로, 예상하지 못한 구현 예외는 마스킹된 ERROR로 구분한다.
- 모든 대용량 녹화 파일은 NAS에만 저장하고 Supabase Storage 복사본과 TUS 동기화는 사용하지 않는다. DB는 NAS 저장소 식별자와 상대 경로를 포함한 녹화 메타데이터만 보관한다. 기존 Storage 객체는 별도 승인 없이 삭제하지 않는다.
- 웹에서 재생하는 영상은 PC가 온라인일 때의 LiveKit 실시간 스트리밍으로 한정한다. 녹화본은 웹 내 재생하지 않고 NAS에서 다운로드만 제공하며, PC가 오프라인이어도 NAS가 접근 가능하면 기존 녹화 목록과 다운로드를 사용할 수 있게 한다.
- NAS1dual URL 서비스의 공개 다운로드 형식은 `http://<NAS_HOST>:<URL_SERVICE_PORT>/publist/HDD1/<공유폴더>/<상대경로>`이고 Range 요청은 지원한다. 그러나 현재 HTTP 전용·CORS 미지원·`application/octet-stream` 응답이며 `publist`는 무인증이므로 녹화 서비스의 최종 인증 경로로 사용하지 않는다.
- 녹화본 다운로드 인증의 우선안은 NAS URL 서비스의 로그인 필요 `list` 경로와 녹화 다운로드 전용 최소권한 계정을 사용하는 것이다. 웹은 NAS 자격증명을 취급하지 않고 DB의 NAS 식별자·상대 경로로 다운로드 링크만 구성하며, 사용자가 NAS 최상위 탭에서 로그인한 뒤 다운로드한다. 현재 HTTP 전용 인증은 자격증명과 세션 보호를 보장하지 못하므로 운영 허용 여부를 별도로 확정하기 전까지 보안상 임시안으로 취급한다.
- 인증 없는 `publist`, URL에 계정·비밀번호 포함, 공용 NAS 계정의 웹 저장, 클라우드의 NAS 직접 접속, PC를 통한 대용량 파일 프록시는 녹화본 다운로드 인증 방식으로 사용하지 않는다.

## 2026-08-14

- NAS1dual에 `dfblackbox-nas.duckdns.org` Let's Encrypt 인증서와 HTTPS를 적용하고 URL 서비스 443·Apache 8443의 인증서 체인과 URL 서비스 Range 응답을 확인했다.
- 인증 없는 `list` 요청은 401/403이 아니라 `200 text/html` 로그인 화면을 반환하므로 웹은 NAS 응답을 재생하거나 검사하지 않고 다운로드 주소를 최상위 새 탭으로 연다.
- DB는 조직별 NAS HTTPS 기준 주소, 카메라 NAS 루트와 녹화 상대 경로를 보관한다. 새 녹화는 Storage 열 없이 카탈로그를 등록하며 기존 Storage 객체와 레거시 행은 삭제하지 않는다.
- `recording-media`는 파일 업로드·완료·재생 signed URL을 제공하지 않고 장치 카탈로그 등록, 사용자 목록과 권한 확인된 NAS 다운로드 주소만 제공한다.
- 웹의 Supabase 로그인 권한은 Edge Function의 RS256 일회성 증명으로 NAS1dual의 8시간 HttpOnly 세션으로 교환한다. 파일별 단기 티켓이나 NAS 공용 자격증명을 DB·웹에 저장하지 않는다.
- NAS 다운로드 Gateway는 NAS에 저장된 공개키로 증명을 검증하고 조직 권한에서 파생된 카메라 경로의 `recordings/*.mp4`만 attachment·Range로 제공한다. 목록·업로드·삭제와 웹 재생은 제공하지 않는다.
- 녹화 목록은 최초 로그인과 사용자의 전체/목록 새로고침에서 DB 카탈로그를 조회한다. 장치별 온라인 표시는 명령 폴링에서 갱신한 공인 IP와 마지막 heartbeat를 기준으로 하며 파일 목록과 독립적으로 갱신한다.
- 실제 NAS의 117,008,916바이트 MP4는 파일 이동이나 클라우드 업로드 없이 DB 카탈로그 `ready` 등록이 확인되었다.
- 신규 녹화 이송은 ipDISK Drive·SMB를 요구하지 않고 내·외부망에서 동일한 NAS HTTPS Gateway를 사용한다. 장치 토큰은 Edge에만 보내며 NAS에는 장치·카메라·NAS 위치·경로가 제한된 1시간 RS256 assertion만 전달한다.
- NAS 업로드는 4MiB 조각과 서버 offset으로 재개하고, NAS가 전체 길이와 SHA-256을 확인한 뒤 같은 볼륨의 최종 `recordings/*.mp4`로 원자적 전환한다. NAS 확정과 DB 카탈로그 `ready` 전에는 로컬 완성본을 자동 삭제하지 않는다.
- 012 마이그레이션과 `recording-media`·NAS Gateway를 원격 배포했다. 4MiB에서 중단한 117,008,977바이트 MP4를 앱 재시작 후 이어올려 로컬·NAS·웹 다운로드 SHA-256 일치, DB `ready`, 웹 목록과 별도 NAS 로그인 없는 다운로드를 확인했다.
- 신규 PC 등록의 NAS 준비는 로컬 SMB 프로비저닝을 사용하지 않는다. 등록 승인 후 Edge가 발급한 카메라 범위 assertion으로 NAS HTTPS Gateway가 표준 폴더를 생성·쓰기 검사하며, 기존 `NasRootFolder` 설정 필드는 JSON 하위 호환용으로만 유지한다.
