# 작업명

트레이 최소화 중복 호출 및 복원 재귀 수정

## 목표

* 트레이 최소화가 여러 번 호출되는 문제를 제거한다.
* 트레이 아이콘 더블클릭 복원 시 발생하는 `StackOverflowException`을 방지한다.

## 배경

* `WindowState = Minimized`가 `Resize`를 발생시키고, `MainForm_Resize()`가 다시 `HideToTray()`를 호출한다.
* 시작 처리와 자동 녹화 완료 처리에서도 `HideToTray()`를 직접 호출해 진입 경로가 중복된다.
* `RestoreFromTray()`가 최소화 상태에서 `ShowInTaskbar`와 `Show()`를 먼저 변경하므로 `Resize → HideToTray()` 재진입이 발생할 수 있다.

## 관련 파일

* `DFBlackbox/Forms/MainForm.cs`

## 변경 금지

* 카메라 연결, 프레임 수신, 녹화 시작·종료 로직은 변경하지 않는다.
* `StartInTray` 설정 형식과 기존 명령행 인수는 변경하지 않는다.

## 요구사항

* 트레이 전환 중임을 나타내는 재진입 방지 상태를 추가한다.
* `HideToTray()`와 `RestoreFromTray()`를 여러 번 호출해도 한 번만 처리되는 멱등 구조로 만든다.
* 복원 시 `WindowState = Normal`을 `Show()`보다 먼저 적용한다.
* 트레이 전환 중 발생한 `Resize`에서는 다시 `HideToTray()`를 호출하지 않는다.
* 최초 실행 시 `WindowState = Minimized`와 직접 `HideToTray()`가 중복되지 않도록 한 경로로 통합한다.
* 자동 녹화 완료 시 이미 트레이 상태라면 다시 최소화하지 않는다.
* 가능하면 설정 로드 전후로 중복 호출되는 `InitializeTrayIcon()`도 한 번의 유효한 초기화 흐름으로 정리한다.

## 완료 조건

* 최소화 한 번에 `HideToTray()`가 한 번만 수행된다.
* 트레이 아이콘 더블클릭과 컨텍스트 메뉴 `열기`로 정상 복원된다.
* 빠르게 최소화·복원을 반복해도 재귀 호출, 화면 깜박임, `StackOverflowException`이 발생하지 않는다.
* 트레이에서 자동 녹화와 프레임 수신이 계속 유지된다.
* 빌드가 경고와 오류 없이 완료된다.

## 테스트 방법

* 일반 실행 후 최소화하고 트레이 아이콘 더블클릭으로 10회 이상 반복 복원한다.
* `트레이에서 시작`을 켠 상태에서 일반 녹화 모드와 자동 녹화 모드를 각각 실행한다.
* USB 웹캠 자동 녹화 시작 전후에 트레이 이동이 한 번만 발생하는지 로그 또는 디버거로 확인한다.
* 트레이 메뉴의 `열기`와 `종료`가 각각 한 번만 실행되는지 확인한다.
* `dotnet build DFBlackbox\DFBlackbox.csproj -o .buildcheck`를 실행한다.

## 결과

* `_trayTransitionInProgress`, `_trayHidePending`, `_isHiddenToTray` 상태를 추가해 트레이 숨김·복원 재진입과 중복 예약을 차단했다.
* `Resize` 이벤트에서는 즉시 숨기지 않고 UI 메시지 처리 이후 `HideToTray()`를 한 번만 실행하도록 변경했다.
* 최초 실행 시 `WindowState = Minimized`와 직접 숨김이 겹치던 경로를 단일 예약 호출로 정리했다.
* 복원 순서를 `WindowState = Normal` → `ShowInTaskbar = true` → `Show()`로 변경해 최소화 상태의 `Resize` 재귀를 제거했다.
* 자동 녹화 완료 시 이미 트레이에 있으면 `HideToTray()`가 즉시 반환하도록 멱등 처리했다.
* 설정 로드 전후 두 번 생성되던 트레이 아이콘 초기화를 설정 로드 후 한 번으로 줄였고, 언어 변경으로 다시 만들 때 기존 표시 상태를 유지하도록 했다.
* `dotnet build DFBlackbox\DFBlackbox.csproj -o .buildcheck` 결과 경고 0개, 오류 0개로 성공했다.
* 실제 USB 웹캠 자동 녹화 상태에서 최소화·더블클릭 복원을 반복하는 수동 회귀 테스트는 실행 환경에서 확인이 필요하다.
* 후속 검증에서 작업표시줄 표시만 복구되고 창이 나타나지 않는 문제가 확인되어, 복원 순서를 `ShowInTaskbar` → `Show()` → `WindowState = Normal` → `BringToFront()` → `Activate()`로 조정했다.
* `_isHiddenToTray`는 실제 표시와 활성화가 완료된 뒤에만 해제하며, 다른 스레드에서 복원이 요청되면 UI 스레드로 전달하도록 보완했다.
