# 작업명

NAS HTTPS 직접 이어올리기와 오프라인 복구

## 목표

DFBlackbox가 ipDISK Drive·SMB 드라이브 없이 내·외부망에서 동일한 NAS HTTPS Gateway로 완성 MP4를 직접 전송한다. PC 또는 NAS 연결이 끊기면 로컬 완성본을 보존하고, 연결 복구 후 중단 지점부터 이어올려 NAS 확정 저장과 DB 카탈로그 등록을 완료한다.

## 예정 구현 범위

* A. DB·Edge Function에 장치 토큰으로 카메라별 NAS 업로드 범위를 확인하고 서명된 업로드 세션을 발급하는 계약을 추가한다. (완료: 2026-08-14)
* B. NAS1DUAL PHP Gateway에 공개키 검증, 조각 업로드, offset 조회, 이어올리기, 길이·SHA-256 검증과 최종 MP4 전환을 구현한다. (완료: 2026-08-14)
* C. DFBlackbox의 SMB 복사를 NAS HTTPS 전송으로 교체하고, 오프라인·NAS 단절 중 로컬 보존과 연결 복구 재시도를 구현한다. (완료: 2026-08-14)
* D. 원격 DB·Edge·NAS를 배포하고 내·외부망, 중단·복구, DB 카탈로그, 웹 목록·다운로드를 통합 검증한다. (완료: 2026-08-14)

## 진행 현황

잔여 작업 0개

* 세부 작업은 한 번에 하나만 진행하고 완료한 식별자를 잔여 목록에서 제거한다.
* 추가 발견 과제는 현재 단계에 임의로 포함하지 않고 별도 지시 대상으로 분리한다.
* 작업서 내부 단계에서는 정적 계약만 확인하고 Release 빌드·publish는 D 종료 시 한 번 수행한다.

## 정책·보안 경계

* 내부망과 외부망 모두 DB에 등록된 NAS HTTPS Gateway를 사용하며 `S:` 드라이브와 ipDISK Drive를 요구하지 않는다.
* 대용량 파일 바이트는 DFBlackbox에서 NAS로 직접 전송하고 Supabase를 통과하거나 Storage에 저장하지 않는다.
* NAS 단절 중에는 완성 MP4를 로컬에 임시 보존하고, NAS 확정 저장 전에는 자동 정리하지 않는다.
* 장치 토큰과 서명 개인키는 NAS·DB·문서·로그에 기록하지 않는다. NAS에는 공개키만 둔다.
* 업로드 권한은 활성 장치의 단일 카메라·NAS 위치·카메라 상대 경로로 제한한다.
* NAS Gateway는 임시 업로드와 최종 전환만 허용하고 임의 경로 탐색·삭제·파일 덮어쓰기를 제공하지 않는다.

## 결과

* A: 활성 장치 토큰과 카메라 소유관계를 확인해 NAS 위치·HTTPS Gateway·카메라 상대 경로만 반환하는 service-role RPC를 추가했다.
* A: `recording-media`에 1시간 장치 업로드 세션을 추가했다. NAS는 기존 공개키로 장치·카메라·NAS 위치·경로 범위가 포함된 별도 audience의 RS256 증명을 검증할 수 있다.
* A: 업로드 URL과 권장 4MiB 조각 크기를 응답하되 NAS 계정·장치 토큰·절대경로는 포함하지 않는다. 원격 적용과 실제 응답 검증은 D에서 수행한다.
* B: NAS PHP 7.3 Gateway에 `POST` 생성, `HEAD` offset 확인, `PATCH` 4MiB 조각 이어쓰기와 `POST` 완료 계약을 추가했다.
* B: 임시 데이터·상태·잠금 파일은 서명된 카메라 경로의 `temp/dfblackbox-uploads`에만 생성한다. 상대 경로와 symlink 경계를 다시 확인하고 기존 최종 파일은 덮어쓰지 않는다.
* B: 전체 길이와 SHA-256이 일치할 때만 같은 NAS 볼륨의 `recordings` 아래로 원자적 변경한다. 불일치 시 임시 파일을 0바이트로 되돌려 처음부터 재시도할 수 있다.
* B: 로컬 PHP 실행기가 없어 괄호·경로·메서드 계약과 diff 공백을 정적으로 확인했다. NAS PHP 7.3 구문·실제 조각 전송은 D 배포 전에 수행한다.
* C: 앱 실행 경로에서 SMB 복사 서비스를 제거하고 로컬 완성 MP4를 Edge 발급 세션으로 NAS HTTPS Gateway에 4MiB씩 직접 이어올리도록 변경했다.
* C: NAS가 반환한 offset부터 로컬 파일 스트림을 재개하며, NAS 확정과 DB 카탈로그 `ready`가 모두 끝난 파일만 보존기간 정리 대상으로 인정한다. 실패 파일은 로컬에 남겨 1분 주기 또는 녹화 완료 신호로 재시도한다.
* C: Supabase publishable key와 장치 토큰을 NAS 요청에 전달하지 않고, NAS에는 세션 assertion만 전송하도록 HTTP 클라이언트를 분리했다. Release 빌드·실환경 검증은 D에서 한 번 수행한다.
* D: 012 마이그레이션, `recording-media` Edge Function과 NAS Gateway를 배포했다. 세션 없는 NAS 업로드·다운로드는 401, 설정 직접 접근은 403, 잘못된 장치 토큰의 업로드 세션 발급은 401로 거부됨을 확인했다.
* D: 고유한 117,008,977바이트 MP4의 첫 4MiB만 전송하고 중단한 뒤 최신 Release 앱을 시작했다. NAS가 반환한 4,194,304 offset부터 나머지를 이어올려 전체 길이·SHA-256 확정과 DB 카탈로그 `ready`를 완료했다.
* D: 로그인된 웹을 새로고침하자 새 녹화가 112MB 다운로드 항목으로 나타났고 별도 NAS 로그인 없이 다운로드됐다. 로컬 원본, NAS 최종본, 다운로드 파일의 크기와 SHA-256이 모두 일치했고 다운로드 MP4의 첫 영상 프레임 디코딩도 성공했다.
* D: Release 빌드는 경고 0개·오류 0개였고 self-contained 단일 파일 publish가 성공했다. 미래 시각으로 잘못 만든 실패 테스트 파일만 로컬과 NAS에서 제거했으며 성공한 NAS 카탈로그 항목과 다운로드 파일은 보존했다.
