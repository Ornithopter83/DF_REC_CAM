# 작업명

NAS 녹화물 카탈로그와 인증 다운로드 전환

## 목표

완성된 대용량 MP4는 NAS에만 유지하고 DB에는 녹화 메타데이터와 NAS 상대 경로만 등록한다. 웹은 녹화본을 재생하지 않고 권한이 확인된 사용자에게 NAS 다운로드만 제공한다.

## 예정 구현 범위

* A. NAS 파일 발견, 안정화 판정과 중복 방지 경계를 정리한다. (완료: 2026-08-13)
* B. 기존 TUS 이어올리기 구현을 점검하고 URL 검증을 보완한다. (완료 후 정책 변경으로 폐기 대상: 2026-08-13)
* C. `RecordingCloudSyncService`와 TUS·Supabase Storage 업로드를 비활성화하고 NAS 메타데이터 등록 흐름으로 전환한다. (완료: 2026-08-14)
* D. `recording-media`를 Storage signed URL API에서 조직 권한·NAS 카탈로그·다운로드 경로 API로 전환한다. (완료: 2026-08-14)
* E. NAS 인증 다운로드 경로를 확정하고 웹 녹화 목록의 동작을 다운로드 전용으로 연결한다. (완료: 2026-08-14)

### A. 파일 발견·안정화·멱등성 결과

* 등록된 NAS 카메라의 `recordings` 루트만 재귀 검색하고 `.mp4` 중 `.recording.mp4`, `.crashed.mp4`, `.uploading.mp4`를 제외한다. 상대 경로가 루트 밖으로 벗어나는 항목은 업로드하지 않는다.
* 파일 수정 후 최소 5초가 지나야 후보가 되며, 최초 길이·UTC 수정시각을 읽은 뒤 2초 후 같은 값을 다시 확인한다. 복사·작성 중인 파일과 이름만 먼저 나타난 파일은 다음 1분 검사로 미룬다.
* 상태 키는 장치 ID·카메라 ID·NAS 상대 경로 조합이고 길이·수정시각이 같은 `ready` 항목은 다시 해시하거나 업로드하지 않는다. 같은 경로의 파일이 교체되면 메타데이터 변화로 새 SHA-256을 계산한다.
* 서버 멱등 키는 장치가 계산한 SHA-256이며 DB는 장치·카메라·fingerprint 유일 제약을 사용한다. 파일이 다른 NAS 경로로 이동해도 내용이 같으면 기존 녹화 레코드와 Storage 객체를 재사용한다.
* A 범위에서 작성 중 파일 선택이나 동일 파일 중복 업로드 결함은 발견되지 않아 현재 구현을 유지했다.

### B. TUS 이어올리기 결과

* TUS 생성 직후 서버가 반환한 Location을 상태 파일에 원자적으로 저장한다. PATCH 응답이 유실되거나 앱이 종료돼도 다음 검사에서 HEAD로 서버 offset을 다시 읽고 해당 위치부터 파일을 이어 올린다.
* 저장된 Location은 새 업로드 세션의 endpoint와 scheme·host·port가 같고 endpoint 하위 경로인 경우에만 사용한다. 상태 파일이 변조되거나 잘못된 URL이 남아 있어도 새 TUS 서명을 외부 origin으로 보내지 않는다.
* TUS HEAD가 400·401·403·404·409·410·412를 반환하면 위치가 만료·충돌·소실된 것으로 보고 기존 Location을 폐기한 뒤 새 세션을 생성한다.
* 새 업로드 생성 응답의 상대·절대 Location도 같은 endpoint 경계를 통과해야 저장하고 PATCH한다. 사용자 정보가 포함된 URL과 다른 origin·경로는 `InvalidDataException`으로 거부한다.
* 파일은 `FileShare.Read`로 열어 업로드 중 다른 writer가 새 쓰기 handle을 만들지 못하게 하고, 각 6 MiB 이하 PATCH 뒤 정확히 증가한 offset만 수용한다.

### C. 기존 Storage 제한 확인 결과와 정책 전환

* 2026-08-13 Supabase Management API 읽기 전용 조회 결과 프로젝트 전역 Storage 파일 제한은 52,428,800바이트(50 MiB)다. 버킷별 제한이 `null`이어도 전역 제한이 우선 적용된다.
* 현재 실행 설정의 2.5 Mbps·10분 분할은 영상 데이터만 약 187.5 MB이며 컨테이너 여유분을 포함하면 최소 256 MiB 전역 제한이 필요하다. 현재 50 MiB에서는 설정된 분할 파일을 업로드할 수 없다.
* UI가 허용하는 최대 2.5 Mbps·1,440분을 그대로 지원하려면 약 27 GB 이상이 필요하지만, 운영상 과도하므로 실제 최대 분할 정책을 먼저 확정해야 한다.
* 2026-08-13 정책 변경으로 대용량 파일은 NAS에만 저장한다. 따라서 Storage 제한 상향이나 녹화 분할 축소는 수행하지 않고, 기존 Storage 업로드 구현을 제거하는 근거로 사용한다.

### C. NAS 카탈로그 등록 전환 결과

* 데스크톱은 NAS의 안정화된 MP4를 SHA-256으로 식별한 뒤 파일 바이트를 전송하지 않고 카메라·NAS 상대 경로·파일명·크기·녹화 시각만 등록한다.
* TUS 세션 생성, HEAD/PATCH 이어올리기와 Storage 완료 확인 호출을 제거했다. 기존 Storage 객체와 레거시 DB 행은 삭제하지 않는다.
* 카탈로그 상대 경로는 등록된 카메라 NAS 경로 아래 `recordings/`로 제한하고 로컬 SMB 루트와 NAS 계정은 API로 보내지 않는다.

### D. DB·API 전환 결과

* `202608140009_nas_recording_catalog.sql`에 조직별 NAS 위치, 카메라 NAS 연결, 녹화 NAS 상대 경로와 카탈로그 등록 RPC를 추가했다.
* 기존 Storage 열은 레거시 호환을 위해 선택 필드로 유지하되 새 카탈로그 목록은 NAS 위치가 있는 항목만 반환한다.
* `recording-media`는 업로드·완료·재생 URL 경로를 제거하고 장치 카탈로그 등록, 사용자 목록, NAS 다운로드 URL만 제공한다.
* 다운로드 주소는 DB의 HTTPS 기준 주소와 경로 세그먼트를 서버에서 결합하며 사용자 정보·질의·fragment가 있는 기준 주소와 경로 이탈을 거부한다.

### E. NAS 인증 다운로드 확인 결과

* NAS에 Let's Encrypt 인증서를 적용했고 `https://dfblackbox-nas.duckdns.org`의 443·8443 인증서 이름·체인·유효기간 검증이 성공했다.
* URL 서비스 HTTPS 파일 요청에서 `206 Partial Content`, `Accept-Ranges: bytes`와 올바른 `Content-Range`를 확인했다.
* `publist`는 인증 없는 공개 경로이므로 녹화본에 사용하지 않는다. 우선 검증할 인증 경로는 로그인 필요 `list/HDD1/<공유폴더>/<상대경로>`와 녹화 다운로드 전용 최소권한 NAS 계정 조합이다.
* 인증 없는 `list` 파일 요청은 401/403 대신 `200 text/html` 로그인 화면을 반환한다. 웹은 NAS 응답을 미디어로 해석하지 않고 다운로드를 최상위 새 탭으로 열어 사용자가 NAS에서 직접 로그인하게 한다.
* 웹과 DB에는 NAS 계정·비밀번호·세션을 저장하지 않는다. DB는 NAS 식별자·HTTPS 기준 주소·상대 경로만 보관한다.
* URL에 자격증명을 넣는 방식, 공용 계정 저장, 무인증 난수 경로, 클라우드 또는 PC의 대용량 파일 프록시는 사용하지 않는다.

* B 작업에서 저장된 TUS Location과 새 Location을 현재 endpoint의 동일 origin·하위 경로로 제한하고 만료·충돌 응답은 새 세션으로 전환하도록 보완했다.
* C 사전 확인에서 프로젝트 전역 Storage 제한 50 MiB가 현재 2.5 Mbps·10분 분할의 예상 약 187.5 MB보다 작음을 확인했다. 이후 모든 대용량 파일을 NAS에만 저장하는 정책으로 전환해 제한 상향·분할 축소 대신 Storage 업로드 경로를 폐기한다.
