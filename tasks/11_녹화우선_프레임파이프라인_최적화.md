# 작업명

녹화 우선 프레임 파이프라인 최적화

## 목표

* USB 카메라 녹화 중 프리뷰와 UI 처리 때문에 녹화 프레임이 감소하지 않도록 한다.
* 녹화 중에는 녹화 writer를 최우선으로 처리하고 프리뷰는 낮은 주기로 최소 기능만 제공한다.
* FFmpeg 입력 과정의 프레임별 BMP 인코딩 비용을 제거한다.

## 원인

* 캡처 루프에서 녹화 writer 호출, 프리뷰 확대, Bitmap 변환과 UI 갱신이 순차적으로 실행된다.
* FFmpeg 입력 전에 매 프레임을 BMP로 인코딩하고 파이프를 즉시 flush하여 캡처 루프가 인코딩 처리에 묶인다.
* 라이브 프리뷰가 원본 크기와 관계없이 높이 1080으로 확대된다.

## 구현 기준

* 실제 녹화 writer는 전용 bounded queue 작업에서 실행한다.
* FFmpeg에는 고정된 녹화 크기의 `bgr24 rawvideo`를 전달한다.
* 녹화 중 프리뷰는 최대 5 FPS, 최대 640x360 크기로 제한한다.
* 프리뷰 제한은 복사, 리사이즈와 Bitmap 변환 전에 적용한다.
* 녹화 중 대시보드 갱신 주기는 1초로 제한한다.
* writer 종료 시 큐를 모두 비운 뒤 파일을 정상 마무리하고 모든 `Mat`을 해제한다.

## 완료 조건

* 녹화 writer 작업이 캡처 루프와 분리된다.
* 녹화 중에도 출력 FPS가 설정된 녹화 FPS에 최대한 근접한다.
* 녹화 종료 파일이 정상 재생되고 종료 또는 예외 시 큐의 프레임이 누수되지 않는다.
* 빌드가 경고와 오류 없이 완료된다.

## 테스트 방법

* USB 카메라 프리뷰 FPS와 녹화 중 FPS를 비교한다.
* 작업 관리자에서 `DFBlackbox.exe`와 `ffmpeg.exe` CPU 사용량을 각각 비교한다.
* 10분 이상 녹화 후 파일의 길이, FPS, 끊김 여부를 확인한다.
* 녹화 시작과 중지를 반복하고 빈 파일 또는 종료 예외가 발생하지 않는지 확인한다.

## 결과

* 실제 writer 앞에 최대 4~15프레임의 bounded queue를 두고 전용 작업에서 프레임을 순차 기록하도록 변경했다.
* writer 큐는 `Mat` 복제본의 소유권을 가져가 소비 직후 해제하며, 종료 시 남은 큐를 비운 뒤 FFmpeg를 마무리한다.
* FFmpeg 입력을 프레임별 BMP 인코딩에서 `bgr24 rawvideo`로 변경하고 매 프레임 flush를 제거했다.
* H.264 소프트웨어 인코더에는 `veryfast` preset을 적용했다.
* 녹화 중 프리뷰를 최대 5 FPS, 640x360으로 제한하고 1080 높이 확대 및 일반 오버레이 처리를 생략했다.
* 녹화 중 최신 프레임 스냅샷 복사도 5 FPS로 제한하고 대시보드 갱신 주기를 1초로 낮췄다.
* 수동·전체 녹화에서는 감지 알고리즘을 제외하고 자동 감지 녹화 또는 디버그 표시가 필요할 때만 유지한다.
* 카메라 수신 FPS와 writer 기록 FPS를 분리해 카메라 상태와 녹화 상태에 각각 표시하도록 변경했다.
* FFmpeg rawvideo 입력으로 만든 320x240, 30 FPS 샘플이 H.264/yuv420p, 1초/30프레임 MP4로 정상 생성·디코딩되는 것을 확인했다.
* 실제 USB 웹캠의 장시간 녹화 FPS와 CPU 사용량은 실행 환경에서 수동 확인이 필요하다.
