# 작업명

신규 등록 NAS 준비와 다운로드 권한 범위 갱신

## 목표

신규 장치의 첫 NAS 준비 요청이 상태 순환 때문에 401로 실패하지 않게 하고, 등록 PC명의 공백을 보존하며, 새 카메라 등록 뒤 기존 NAS 로그인 세션의 다운로드 범위를 갱신한다.

## 세부 작업

* A. `approved` 신규 장치도 장치 토큰과 카메라 소유권 확인 후 NAS 준비 세션을 발급받게 한다. (완료: 2026-08-14)
* B. 신규 카메라의 NAS 폴더 세그먼트에서 등록 PC명의 내부 공백을 보존한다. (완료: 2026-08-14)
* C. 웹 전체 새로고침에서 NAS SSO 권한 범위를 다시 발급받아 새 카메라 다운로드를 허용한다. (완료: 2026-08-14)
* D. DB·웹 배포, Release 빌드·publish와 최소 회귀 검사를 수행한다. (완료: 2026-08-14)

## 진행 현황

잔여 작업 0개

## 정책·보안 경계

* NAS 세션 발급은 등록 상태 외의 기존 장치 토큰·카메라 소유권·활성 NAS 위치 검증을 완화하지 않는다.
* NAS 경로는 Windows 금지문자와 제어문자를 계속 치환하고, 내부 공백만 보존한다.
* 기존 NAS 폴더와 DB 카탈로그 경로는 자동 이동하지 않는다.
* NAS SSO 갱신은 사용자 웹 로그인으로 새 assertion을 발급받으며 NAS 공용 자격증명을 저장하지 않는다.

## 결과

* A: NAS 준비 이전 상태인 `approved` 장치도 기존 장치 토큰·폐기 여부·카메라 소유권·활성 NAS 위치 검증을 통과하면 HTTPS 준비 세션을 발급받도록 014 마이그레이션을 추가했다. 최초 401 실패 보고으로 `active`가 된 뒤 재시도해야 했던 상태 순환을 제거했다.
* B: 신규 승인 함수가 카메라 NAS 경로를 만들 때 등록 PC명의 내부 공백을 제거하지 않도록 015 마이그레이션을 추가했다. Windows 금지문자·제어문자 치환, 끝 공백·점 제거와 길이 제한은 기존 정규화 함수로 유지한다.
* C: 포털 루트의 브라우저 전체 새로고침과 포털 전체 새로고침 버튼에서 사용자 웹 로그인으로 NAS SSO assertion을 다시 발급받도록 변경했다. NAS 인증 교환에서 돌아온 `nas_sso=ready` 요청은 기존 상태를 이어 처리해 리디렉션 반복 없이 새 카메라 경로가 세션 허용 범위에 포함된다.
* D: 014·015 마이그레이션 dry-run에서 두 파일만 적용 대상임을 확인한 뒤 원격 Supabase에 적용했고 로컬·원격 001~015가 일치함을 확인했다.
* D: 웹 JavaScript 구문 검사와 변경 파일 diff 검사를 통과했다. 실제 NAS 서버 시각은 로컬 시각과 1초 이내로 일치해 시각 지연이 401 원인이 아님을 확인했다.
* D: 요청된 `DFBlackbox/MyCompany/15F4호기/recordings/manual/20260622_171821.mp4`는 실제 NAS에 존재했다. 기존 NAS SSO 세션 범위에 신규 카메라가 빠져 `Recording not found`가 발생한 것으로 판정했다.
* D: Release 빌드는 경고 0개·오류 0개였고 self-contained 단일 파일 publish가 성공했다.
