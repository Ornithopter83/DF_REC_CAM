# 작업명

USB 자동녹화 시작 안정화 및 빈 파일 종료 오류 수정

## 목표

* USB 웹캠 자동 전체 녹화가 정상적인 MP4 파일을 생성하도록 한다.
* 카메라를 연 뒤 오토포커스 안정화를 위해 10초 대기하고 녹화를 시작한다.
* 녹화 실패 후 종료할 때 `FileNotFoundException`이 연쇄 발생하지 않도록 한다.

## 원인

* UI 자동 시작 경로와 캡처 루프가 동시에 분할 로직에 진입해, 다음 분할 시각 설정 전에 새 writer를 즉시 종료할 수 있었다.
* 전체 녹화 시작 시 전달한 최신 프레임을 크기 계산에만 사용하고 실제 FFmpeg 입력에는 기록하지 않았다.
* FFmpeg 종료 실패 시 writer 상태가 남았고, 다음 종료에서 존재하지 않는 임시 파일을 이동했다.

## 관련 파일

* `DFBlackbox/Forms/MainForm.cs`
* `DFBlackbox/Core/RecordingService.cs`
* `DFBlackbox/Utils/Localization.cs`

## 요구사항

* 전체 녹화 시작과 분할 처리를 직렬화하고 writer 공개 전에 다음 분할 시각을 확정한다.
* writer 생성 직후 최신 프레임을 실제 첫 프레임으로 기록한다.
* 시작 또는 종료 실패 시 writer와 프레임 자원을 항상 정리한다.
* 임시 파일이 존재할 때만 최종 MP4로 이동한다.
* USB 카메라는 첫 프레임 수신 후 10초간 프리뷰를 유지한 뒤 자동 녹화를 시작한다.
* IP 카메라에는 추가 10초 대기를 적용하지 않는다.
* 자동 전체녹화 대기 중 수동 또는 자동 감지 모드로 전환하면 예약 타이머, 첫 프레임 대기와 USB 워밍업을 즉시 취소한다.

## 완료 조건

* 자동 녹화 시작 후 `.recording.mp4`가 생성되고 정상 종료 시 `.mp4`로 변경된다.
* FFmpeg가 실패해도 이후 종료에서 `FileNotFoundException`이 발생하지 않는다.
* USB 카메라 자동 시작은 첫 프레임 수신 후 약 10초 뒤 진행된다.
* 빌드가 경고와 오류 없이 완료된다.

## 테스트 방법

* USB 웹캠 자동 전체 녹화를 시작하고 10초 워밍업 이후 파일 크기가 증가하는지 확인한다.
* 녹화를 종료하고 생성된 MP4가 재생되는지 확인한다.
* 녹화 파일 분할 시간이 지난 뒤 새 MP4가 연속 생성되는지 확인한다.
* 자동 녹화를 여러 번 시작·종료해 `FileNotFoundException`이 재발하지 않는지 확인한다.
* `dotnet build DFBlackbox\DFBlackbox.csproj -o .buildcheck`를 실행한다.

## 결과

* 전체 녹화 회전 경로에 동기화를 추가하고 다음 분할 시각을 writer 시작 전에 설정했다.
* 전체 녹화 시작 시 최신 카메라 프레임을 FFmpeg의 첫 입력 프레임으로 기록하도록 변경했다.
* 시작·종료 예외 시 writer, 마지막 프레임, 사전 버퍼 상태를 정리하도록 보완했다.
* FFmpeg가 파일을 만들지 못한 경우 `File.Move()`를 호출하지 않고 원인에 맞는 오류를 반환하도록 변경했다.
* USB 카메라는 첫 프레임 수신 후 10초 워밍업을 거쳐 자동 녹화를 시작하도록 변경했다.
* 자동 전체녹화 예약에 취소 토큰을 연결하고 수동 모드 선택 및 수동 녹화 시작 시 기존 예약과 실행 중인 대기를 취소하도록 변경했다.
* 각 비동기 대기 이후와 전체녹화 시작 직전에 현재 녹화 모드를 다시 검사해 취소된 자동 작업이 전체 모드를 재선택하지 못하도록 했다.
* `dotnet build DFBlackbox\DFBlackbox.csproj -o .buildcheck` 결과 경고 0개, 오류 0개로 성공했다.
* 실제 USB 웹캠 오토포커스와 장시간 분할 녹화 검증은 실행 환경에서 수동 확인이 필요하다.
